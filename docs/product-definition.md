# StoreSpark 产品定义初稿

文档版本：0.2。更新日期：2026-10-28。

本稿基于项目发起人的需求描述。发起人是 IT 实现人员，无法代商家提供准确的业务答案。商家使用情况为发起人转述，目前尚无商家访谈原始记录、内容样本或消费者测试结果。明确要求及讨论依据见[需求与决策记录](discovery-log.md)。

## 产品概念

面向餐饮店主和门店、品牌运营人员，通过对话与已有素材提交，帮助用户把经营诉求收敛成具体宣传任务；拟结合门店真实信息和公开市场信息，提出传播方向，生成适配不同场景的营销内容，并给出使用与验证建议。期望结果是吸引消费者进店尝试。

## 定义要素

| 项目 | 当前定义与状态 |
|---|---|
| 名称 | 项目工作名 StoreSpark；中文候选名店有招，待最终确认。名称尚未查重。 |
| 目标用户 | 餐饮店主、门店运营、品牌运营人员；后续考虑扩展到快消行业。 |
| 核心场景 | 以吸引消费者进店为目标的宣传任务。已讨论的真实需求案例为东北蒸饺在南方或江苏开店，具体商家情况尚未细谈。 |
| 问题 | 据发起人反馈，商家已尝试多种 AI 工具，对内容质量、美观度及吸引力仍不满意。具体原因待访谈和样本分析确认。 |
| 价值主张 | 帮助商家把门店特色转化为宣传方向及可使用内容，降低任务表达、内容构思和制作的负担。改善幅度待验证。 |
| 产品形态 | 支持对话和素材提交的营销助手。当前开始实现 Python API 与 Web 工作台，未来 Linux 部署，并考虑独立小程序客户端共用 API。 |
| 核心能力 | 追问澄清需求、理解已有资料、分析公开信息、提出传播方向、多格式内容创作、提供使用和验证建议。 |
| 单次交付 | 一个明确的宣传方向及其依据、一组适配本次任务的可用成品、对应的使用和验证建议。该交付组合已获发起人认可。 |
| 首版范围 | 餐饮优先；支持需求明确或模糊、有素材或零准备的用户。具体场景、渠道、格式及优先顺序尚未确定。 |
| 暂不包含的建议 | 助手建议先不包含自动发布、广告投放和代运营。该边界尚未获得单独确认，不能视为最终首版范围。 |
| 成功标准 | 建议评估商家能否确认方向、成品能否通过审核并使用、是否减少完成任务的时间；进店效果需另外验证。质量门槛和量化指标待定。 |
| 关键假设 | 公开信息可以帮助理解消费者及提炼传播切入点；产出能改善现有内容；低准备程度用户能通过低负担交流补齐必要信息；内容改善有助于激发进店意愿。均待验证。 |

## 已确认的使用要求

- 用户可以用自己的经营语言开始，不需要懂技术或编写专业提示词。
- 需求清晰时承接明确任务；需求模糊时通过有针对性的追问帮助收敛。
- 已有素材有提交入口，产品应结合素材理解任务；没有素材也能开始交流，并逐步补充必要信息。
- 对话和素材可以共同使用，不按店主能力或准备程度排除其中一类用户。
- 支持多场景、多格式方向。讨论中提到易拉宝、短视频、社交内容、外卖页面、大众点评和小红书等，尚未形成首版支持清单。

## 交付与信息边界

公开信息分析用于支持宣传判断，不能直接证明消费者心智或到店效果。涉及菜品、价格、门店位置及活动等真实信息，成品使用前需商家确认。

脚本、分镜和视频成片是不同交付物；支持某种格式时，应明确可使用成品的标准，不能将脚本视为视频交付完成。
