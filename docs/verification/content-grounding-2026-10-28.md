# 宣传事实与追问质量修复验证

日期：2026-10-28。关联 [#7](https://github.com/Eclipseic1848/StroeSpark/issues/7)，继续推进 [#4](https://github.com/Eclipseic1848/StroeSpark/issues/4)。

## 本轮结论

最终规则在四组冻结输入的真实 DeepSeek Flash 检查中通过有限匹配和逐字段人工复核：不把未提供的属性补成正文事实，不在其他栏目再次索答已知用途，候选建议与正文分开，同时保留用户已明确确认的定位。

生产改动仅在 `storespark/workflow.py`：补来源和提问规则，并将传给模型的既有文案标记为 `source=draft`。没有关键词替换、正文删词、额外模型审稿调用、自动重试、数据库迁移或新增依赖；每次业务操作仍只请求一次模型。

这些结果只覆盖本轮合成样本，不保证所有生成均无事实推断，也不构成商家或市场验收。

## 修复机制

旧稿和助手历史输出可以用于修改，但其中的推测不能自动升级为已确认事实。定位、口感、工艺、人群、销量及评价需要用户或素材依据；用户明确确认的定位可以正常使用，不能由定位继续推导制作工艺。

事实不足时采用最小告知结构，字数、吸引力和修辞要求不能成为补充属性的理由。候选创意留在 `direction`，使用说明留在 `usage`，`content` 只放宣传正文和必要占位。

追问先核对描述、素材和用户历史。去重复规则覆盖整个输出，不能把已知用途的重复问题从 `reply` 移到 `missing_facts`。价格、地址等真正未知值仍可留待确认；需要澄清的未知目标、渠道和冲突信息仍允许合理提问。

## 真实对比设计

基准为提交 `7f0d3fa` 的旧上下文构建规则。[冻结输入](../../tests/fixtures/content_grounding.json)来自此前测试记录，保留文字、原图和历史消息；基准与候选不会共享新生成回复或成品，避免前一轮输出污染后一轮。

对比脚本逐项断言：两边除系统规则和草稿来源标记外，任务、素材和消息一致。模型、基础地址及请求参数保持一致，没有固定采样种子，因此不能用这组小样本估计长期错误率。

| 样本 | 针对的问题 | 最终实际结果 |
|---|---|---|
| 店名、菜名文字素材 | 为凑字数擅自增加定位、口感、销量等属性 | 仅使用店名菜名与未知占位，没有观察到额外门店属性。 |
| 已明确测试用途的菜单图片 | 已知用途被重复索答 | 两菜识别正确，正文为空；逐项检查回复、方向、待确认事项、使用和验证建议，未再询问真假或真实客群。 |
| 含未确认“家常”想法的旧稿 | 旧建议变事实，或候选说明混进正文 | 候选只保留在方向和使用说明，正文没有该定位或编辑建议。 |
| 用户明确确认家常定位 | 修复误伤合法定位，或从定位继续推导工艺 | 正文正常采用确认定位，没有推成家常做法、招牌或受欢迎。 |

## 保留的失败与修正过程

| 阶段 | 真实请求数 | 验收情况 |
|---|---|---|
| 旧规则 baseline | 4 | 复现无依据属性和已知用途重复追问；明确确认定位的输出也曾扩写成招牌信息。 |
| candidate1 | 4 | 未通过人工复核。虽然旧有限检查全为 true，正文仍出现皮薄馅香、顾客常点、家常做法；不能以换词或布尔值全绿判成功。 |
| candidate2 | 4 | 事实忠实和去重复已有改善，但未确认旧稿的条件性编辑建议混入正文。它不是既有定位事实断言，仍违反分栏要求。 |
| candidate3 | 4 | 正文分栏改善，但重复用途问题被移到 `missing_facts`，旧检查只扫 `reply` 因而漏报。 |
| candidate4 最终规则 | 4 | 四组均通过有限检查与独立逐字段人工复核；确认定位没有被机械删除。 |

另有 1 次正常 API 改稿复核，返回 200，新增内容并完整保留旧稿，正文仅含店名、菜名和价格地址占位。该复核发生于 candidate3 期间；最终规则后再次重启正常服务并确认保存配置保留，没有为记录成功重复发模型请求。

合计 21 次真实请求：20 次直接 provider 的受控对比和 1 次正常 API 复核。本轮均取得可解析响应，但有前述语义失败，不能写成全部质量通过。请求记录按输入 SHA 保存，旧版本与失败候选没有覆盖或删除；缓存复核使用当前判定器重新检查，不重复收费请求，也不沿用已经发现漏报的旧布尔值。

[机器可读记录](content-grounding-2026-10-28.json)保留所有阶段的输出、当时的有限检查、输入 SHA 和耗时。本地完整记录还保存在忽略的 `test-results/quality-grounding-20261028/`，未记录密钥。总 token 与实际费用没有完整汇总，不作费用推算。

## 回归与复现

原有 50 项检查加上 4 项上下文契约、10 项有限判定器回归，共 64 项通过。上下文检查覆盖真实 API 调用方的草稿标记、用户确认原文、历史角色、已知答案、文字与图片字节，以及失败时输入和旧成品保留。

判定器回归覆盖原“主打家常”负例、合法候选和已确认定位正例、后续观察到的属性扩写、正文混入条件说明，以及将重复问题移入 `missing_facts` 的漏报。有限反例词表只存在于固定样本测试里，不参与生产过滤，也不能替代人工语义复核。
