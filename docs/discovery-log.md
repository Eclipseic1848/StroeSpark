# StoreSpark 需求与决策记录

记录日期：2026-10-26。依据：本项目产品发现与开发对话。早期记录始于概念定义阶段；当前已有部分实现，最新状态见末尾开发与暂停决定。尚无商家访谈记录或消费者测试结果。

## 用户的原始设想与问题线索

用户希望为线下门店提供智能体或平台：利用互联网信息分析消费者心智及当前品类诉求，帮助某品牌快速生成运营内容、素材和海报，吸引消费者并促进转化。

用户优先考虑餐饮，未来希望沉淀到快消行业。使用者包括个体店主、门店运营和品牌运营人员。当前明确的消费者行动目标是“愿意走进店里尝试”。

具体案例是东北蒸饺店到南方或江苏开店，如何快速引起当地消费者兴趣。用户确认这是一个真实需求，但没有与商家细谈具体困难；没有提供门店身份、位置、菜单、价格、素材样本或经营数据。

据用户反馈，商家已尝试各种 AI 工具，对整体内容质量和美观度不满意。“无法勾起消费者的消费欲望”是用户当前的问题判断，尚无消费者反馈或到店数据佐证。具体不满意的内容类型、制作过程、修改方式、耗时和成本均未核实；不能把“可能都有”“都有”写成完成逐项调研后的结论。

## 已确认的产品要求与共识

| 事项 | 当前共识 |
|---|---|
| 发起人角色 | 用户明确自己是 IT 实现人员，无法代商家提供准确的业务答案；用户的产品与技术判断不等于商家需求验证。 |
| 目标用户 | 店主、门店运营、品牌运营人员；不要求具备技术能力。 |
| 需求清晰度 | 两种情况都支持：明确任务可直接推进；只有经营诉求时通过追问逐步收敛。 |
| 素材准备程度 | 两种情况都支持：已有素材可提交；没有预先准备材料也能开始交流，并按需补充。 |
| 素材提交 | 需要提供提交已有素材的地方，与对话共同作为任务输入；具体材料类型、格式和限制未定。 |
| 场景与格式 | 考虑不同场景、不同格式。用户举例包括易拉宝、短视频、社交网站、外卖平台、大众点评、小红书等；首版清单与优先顺序未定。 |
| 消费者行动 | 希望消费者愿意进店尝试；关注、点赞或商家满意不能直接替代这个目标。 |
| 一次任务交付 | 宣传方向及依据、按需生成的对应成品、使用与小范围验证建议。用户对此回复“可以”。 |
| 项目资料位置 | 用户指定 F:\new branch\StoreSpark 作为项目资料和未来仓库的根目录。 |

多种使用状态需要在同一产品中兼容，不应反复要求用户在“明确或模糊”“有素材或无素材”之间只保留一种。支持多渠道不代表每次任务必须生成所有渠道内容。

## 助手建议与尚未确认的边界

- StoreSpark 为当前项目工作名。中文“店有招”、英文 StoreSpark、宣传语“让门店特色，成为进店理由”由助手提出；中文名和宣传语尚未获用户明确确认，名称也未查重。
- 对话加素材提交是已明确的交互要求；页面布局、智能体架构、技术栈、模型及服务商尚未决定。
- 助手建议先以方向、内容成品和使用建议为交付边界，将自动发布、广告投放、代运营暂不纳入。用户尚未单独确认这一建议，不能视为已批准的首版范围。
- 菜品、价格、活动等真实信息在使用前需要核实，这是内容真实性建议；所需最少材料与审核流程尚未确认。

## 待验证假设与优先事项

1. 找到具体的质量差距：访谈商家，收集一份需求、现有 AI 产物、修改过程和最终认可结果，明确“不满意”的具体表现及判断人。
2. 检查公开信息的实际价值：明确可用来源、时效、访问权限、使用条件和信息可信度，验证其是否有助于提出传播方向。互联网推演不能代替消费者调查。
3. 定义首版可交付范围：围绕一个完整真实任务，明确渠道、文件格式及成品标准；脚本不能计作视频成片，设计草案不能直接计作已可发布物料。
4. 验证使用负担：不同准备程度的用户能否通过少量追问补齐必要信息，以及需要多少时间和修改轮次。
5. 区分内容验收和经营效果：分别观察商家能否采用、时间是否节省，以及消费者反应和进店行为。付费意愿、价格、商业模式和实际转化效果仍未知。

资料缺失可以标为待补充；不得编造门店事实、消费者偏好、市场数据或营销效果。

## 后续对话方法

采用 NPDP 概念开发思路，依次澄清用户、场景、问题、期望利益，再讨论方案、范围和验证。每轮只问 1—3 个关键问题，随回答推进，不一次抛出完整问卷；明确区分用户提供的信息、助手推测和待验证假设。

用户不了解商家细节时，先保留未知；可提出具体、可修正的建议供讨论，不反复追问同一个未知，也不强迫互斥二选一。定期整理当前共识、未决事项和下一步；信息足够时更新产品定义，避免将概念表达清楚误认为需求与效果已验证。

用户已澄清自己的角色是 IT 实现人员，不能通过要求其扮演店主来补齐商家事实。助手可以先提出标注假设的产品流程供讨论；商家事实、偏好与成品效果保持待验证，流程草案不等于已确认的开发范围。
